# Project Memory

## Core
Use Contábil é contabilidade **interna** de uma empresa/grupo — NÃO é sistema para escritório contábil que atende clientes externos. Nunca usar termos como "cliente", "honorários", "empresas atendidas", "escritório contábil" para se referir aos usuários/entidades do sistema. Usar "empresa", "filial", "unidade", "grupo".
Todos os dados fiscais/eSocial/Receita são apenas visuais/mock — sem integração real com órgãos oficiais.
Competência padrão: 2026 (Fev–Jul/2026).
Nunca apagar/limpar/resetar dados (nuvem ou localStorage) automaticamente ao abrir o sistema, nem com base em flag guardada no navegador. Ações destrutivas só por clique explícito do usuário, com caixa de confirmação (AlertDialog). Um "reset único" automático já apagou as empresas da nuvem em todo navegador novo; o teste src/test/primeiroAcesso.test.tsx protege contra isso — mantenha-o passando.

## Visual
Identidade visual "índigo" (atualizada em 2026-09); os tokens ficam em `src/index.css`. `brand-orange` é NOME HISTÓRICO do acento principal e hoje vale ÍNDIGO — não renomear nem voltar para laranja sem varrer os ~790 usos. Avisos e modo prática usam âmbar (`warn`). O menu lateral é uma área escura (classe `dark` no `<aside>` do ContabilShell). Botões: `Button` do design system (variantes default/gradient/success/destructive/outline/soft/ghost/link + prop `loading`). Animações em `src/index.css` (`animate-page-enter`, `.stagger`, `.lift`, `.btn-sheen`), sempre respeitando `prefers-reduced-motion`. Ícones: `lucide-react` 0.462 (conferir se o ícone existe antes de importar).

## Cadastros e contabilidade (2026-09)
- ERP: haverá integração com o ERP da Use Sistemas (ainda não existe). Até lá, os cadastros são alimentados no próprio sistema; o campo `origem` já prevê "ERP".
- **Cadastro único do grupo** (`src/lib/cadastrosStore.ts`): clientes/fornecedores (participantes) e produtos/serviços, em Preparativos › Cadastros. Não criar outros cadastros de parceiros/produtos: os antigos de Financeiro › Cadastros foram removidos (rotas redirecionam). A importação de XML de NF-e alimenta esses cadastros.
- **Núcleo contábil** (área "Contábil"): `planoContasStore.ts` (plano de contas do grupo, centros de custo, históricos padrão; modelo em `planoContasModelo.ts`) e `lancamentosStore.ts` (partidas dobradas, estorno, balancete, razão, diário). Regras: só conta analítica e ativa recebe lançamento; débitos = créditos; competência encerrada (fechamentos do `gestaoStore`) bloqueia lançar/alterar/excluir — corrige-se por estorno.
- **Importação por planilha** (`src/lib/planilha.ts` + `src/lib/importacaoContabil.ts`, telas em `src/components/contabil/ImportacaoPlanilha.tsx`): plano de contas (Contábil › Plano de contas) e balancete de abertura (Contábil › Lançamentos), em CSV ou Excel .xlsx lido no navegador, sem biblioteca externa. O balancete vira **lançamento do tipo "Abertura"** (`origem: "Importação"`, uma partida por conta). Faltando uma conta superior, ela é criada como sintética e o resultado informa quantas.
- **Persistência** (`src/lib/nuvemColecoes.ts`): coleções gravadas na hora no navegador (chave `usecontabil.col.<nome>.v1[.u.<uid>][.pratica]`) e sincronizadas com a tabela `contabil_registros` (jsonb, RLS por usuário, exclusão = marca `excluido`). Novas entidades desse tipo: use `criarColecao()`; não gravar direto na tabela. Modo prática nunca sobe para a nuvem.

## Orientação ao usuário e navegação (2026-10)
- **Camada `src/lib/ux/`** é a fonte única de "o que falta, onde cadastrar, o que isso alimenta, qual o próximo passo". Nada aqui grava ou apaga dados: `contexto.ts` só lê. Toda nova tela com dependência deve declarar `requisitos` em `telas.ts` e, se for uma etapa do ciclo, existir em `fluxo.ts`.
- **Menu por processo** (`src/lib/ux/navModelo.ts`, seções 01–10) é o menu da barra lateral; `src/lib/contabilNav.tsx` (áreas/categorias/módulos) continua sendo a fonte das rotas `/:area/:categoria/:modulo`, do PDF de documentação e da base de rotas — **não remover**. Toda rota nova precisa entrar em `navModelo.ts` (há teste garantindo rota sem ficha e rota repetida; e outro garantindo que endereços clássicos continuam alcançáveis).
- **Componentes `src/components/ux/`**: `BlocoOrientacao` (retorno + contexto + bloqueio) é o que se coloca no topo de cada tela; `ProximosPassos` é o painel de continuação após salvar um cadastro. Se mexer no comportamento deles, rode `npm test -- uxGuiado orientacao`.
- **Consulta pública**: CNPJ e CEP vêm de `src/lib/consultaPublica.ts` (BrasilAPI), sempre por ação explícita do usuário e sem sobrescrever o que já foi digitado. Não duplicar essas funções nas telas.
- **Formulários**: use `Campo*` de `src/components/contabil/cadastros/Campos.tsx` (obrigatório = `*` vermelho, opcional = etiqueta cinza) em vez de `Label + Input` soltos. Todo campo precisa de rótulo ligado (`htmlFor`/`id`) ou `aria-label`.
- **Participante em formulário**: em documento fiscal (e em qualquer tela que peça cliente/fornecedor), use `SeletorParticipante` (`src/components/ux/`) em vez de pedir CNPJ/UF/IE de novo — a herança do cadastro é o padrão e o campo herdado fica somente-leitura enquanto vinculado.
- **CRUDs genéricos** (`CrudDocumentosFiscais`, `CrudEscrituracao`, `CrudTabelaFinanceiro`): já oferecem "Salvar e adicionar outro" (prop `repetir` define o que se repete; o padrão são os `select`/cabeçalho). Ao criar um CRUD novo, siga o mesmo rodapé e mantenha "Salvar" fechando o diálogo.
- **Cabeçalho**: existe um só padrão, o `PageHeader` (com trilha automática). `cadastros/CabecalhoPagina` é adaptador fino dele — não criar um terceiro cabeçalho. `ModulePage` é o renderizador oficial do índice clássico `/:area/:categoria/:modulo` (mantido de propósito).
- **Fichas de tela**: os 102 itens do menu têm ficha própria em `telas.ts`; rotas sem ficha recebem contexto derivado do menu (`fichaDoMenu`). Há teste garantindo que nenhuma rota estática do `App.tsx` cai no texto genérico.
- **Preview de interface**: `npm run dev:preview` sobe o app com `src/preview/supabaseLocal.ts` no lugar do cliente Supabase (alias só quando `UC_PREVIEW=1`). Não usar em produção nem em testes; é apenas para inspecionar a UX sem login.
- **Catálogo de telas**: `src/lib/ux/visoes.ts` + `src/pages/contabil/VisaoGeral.tsx` (`/visao-geral`, `/visao-geral/:secao`, `/visao-geral/:secao/:grupo`) são a vista de conjunto de cada seção — leem `navModelo.ts`/`telas.ts`/`requisitos.ts` e não criam dados. Cada seção do menu tem o item “Visão geral” no topo. Para mexer: `npm test -- visaoGeral`.
- **Modo de uso**: `preferencias.modo` = `guiado` (padrão, com contexto) ou `direto` (lista enxuta, `ContextoTela` começa fechado). Nunca remover o bloqueio por dependência com base nessa preferência — ele é segurança de dado, não didática.
- **Documentação**: `docs/UX_ARQUITETURA_INFORMACAO.md` traz o diagnóstico, o mapa de dependências e o registro das mudanças de UX. Manter atualizado quando a navegação mudar.
